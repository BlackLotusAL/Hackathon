      • 每队恰好 3 人：队长在平台上填写队名和 2 名队员的工号即完成报名，队员会收到通知，不需要确认。

      • 只有队长可以发起挑战、提出申诉、申请成员变更和退赛。
      提交与验证规章 §3.4
      • 主办方为每队在 Codehub 建好仓库，推送到 master 分支的代码就是参赛代码，开发中的代码请放在其他分支。
      • Bot 用 Python 3.9 或 C++17 编写；Python 依赖写在 requirements.txt，只能用公司 PyPI 镜像里已有的包；C++ 在 build.sh 里编译、由 start.sh 启动。
      • 对决开始前，平台固定双方代码版本，并按同一提交规范构建队伍和基准 Bot。对局中的超时和程序退出由裁判按当局规则判定。

      天梯与挑战规章 §5
      • 天梯 Elo 初始分为 1200。同一张随机地图上互换座位的 2 局为一组，双方统一使用 K = 20 计分。队伍在首组结算后入榜。
      • 队伍任一成员可以发起匹配，平台从天梯分相近的队伍里选对手；队长可以挑战任一队伍或基准 Bot，可指定地图种子。
      • 每队同一时间只能有一组本队发起的对局在进行，结束后才能再发起；被别人挑战不受此限。
      • 天梯分不影响晋级、名次或任何参赛结果。天梯对局只对参赛双方开放回放。
      判罚与平台错误规章 §7
      • 程序退出、10 秒内未就绪、累计 10 次错误由裁判程序自动判负，只影响当局。
      • 平台侧故障（裁判异常、超时、容器无法启动、槽位异常）记为平台错误：该局作废并以相同的提交、地图和座位重赛，不罚任何一方。
      • 攻击平台、抄袭、串通操纵单循环或决赛结果、冒名参赛等违规由裁判组认定，最重取消参赛资格。
      申诉规章 §8
      • 只受理事实或计算错误：重算结果与记录不一致、未被识别的平台错误、积分或名次计算有误、处罚的事实认定有误。
      • 初赛单循环结果在积分榜公示后 12 小时内申诉；决赛对决结果在该对决结束后 10 分钟内申诉。天梯对局不受理申诉。
      • 由队长在平台提交，写明对局编号、所依据的条款和证据；仲裁组的决定为终裁。

      曝光领地怎么玩

      双方各写一个程序（Bot），在同一张棋盘上圈地。正常打满 600 回合后比得分。

      比赛的灵感来自光刻用的掩模版。把掩模基板想成一张方格纸，电子束落在上面的点就是你的棋子，规则里叫「束斑」。你的 Bot 每回合给束斑选一个移动方向。

      怎么把格子圈成自己的领地

      从自家领地走出去，沿途画线，再走回自家领地。路线接回领地时，围住的格子就归你，也能圈走对手已占的地。

      • 原有领地
      • 轮廓
      • →束斑和朝向
      • 新圈到的领地

      先认清棋盘上的格子

      正式棋盘有 41×41 格。开局时两边各占一块 3×3 的校准区，束斑从正中心出发，各有 9 分。

      1空白格
      可以走，占下后每格值 1 分。
      3关键图形区
      黄色标出的高分格，可以走，占下后每格值 3 分。
      ×基板缺陷
      撞上就报废。这些格子始终无主。
      校准区
      双方都能进出。两块起点区始终各归自己。
      加速区
      双方整局都能用。从紫框格起步可以加速，格子的分值照原地形算。
      地图坐标与布局细节
      • 左上角是 (0, 0)，x 往右增大，y 往下增大。蓝方（0 号）开局朝上，红方（1 号）开局朝下。开局时只有各自的校准区有归属，也没有轮廓。
      • 把棋盘旋转 180°，空白格、缺陷格和关键图形格的分布相同，两块不重叠的校准区也互相对应。能走的格子都能沿上下左右连通。
      • 每个出生点周围 9×9 范围内，棋盘上的格子都能走，且没有加速区标记点。
      • 三个加速区各有一个区内标记点，标记点彼此不同，到两个出生点的最短路程相等。与最近的等距可通行格相比，每个标记点最多远 2 步。

      一回合怎么走

      每回合两边的 Bot 都看到同一份完整局面，各自有 200 毫秒回复一个方向。只要束斑在场，就必须尝试移动。

      1. 选方向

        U 上D 下L 左R 右

        回复超时、无效，或给出了反方向，束斑就沿原方向走。

      2. 看起步格，决定走几格

        区外起步起→1 格
        加速区起步起→第 1 格→第 2 格

        中途进出加速区，当回合的步数照起步时定好的走。

      3. 一格一格结算

        裁判先查目标格和碰撞。成功走过去后，再查有没有踩到轮廓，最后才留线或圈地。

        加速时两格都沿同一方向走。第一步报废，就走不到第二步。

      哪些情况会报废

      • 踩到轮廓。 踩到谁的轮廓，谁就报废。踩到自己的也算。
      • 撞到缺陷或出界。 束斑自己报废。
      • 束斑相撞。 双方同一步要进同一格，或准备互换位置，目标格在自家领地外的一方报废。

      报废会清掉该方的轮廓，已圈好的领地照常保留。之后停机 5 回合，第 5 个停机回合末从出生点重启。停机期间 Bot 也要回复。

      裁判怎样处理碰撞、同时圈地和重启
      • 裁判先查缺陷和出界，再检查仍要走的束斑之间的碰撞。如果对手本回合已走完，你的束斑可以进入它停留的格子，照常检查轮廓。
      • 双方先移动，再按这一步开始前的轮廓判定谁踩到了谁的线。双方踩线的结果同时生效。报废的束斑停止当回合剩下的移动、留线和闭合，回合结束时离场并清掉轮廓。
      • 一方带着轮廓回到自家领地时，裁判把这方的领地和轮廓当作墙，从棋盘外沿上下左右往里找。这方的轮廓格和外面找不到的格子都算候选，先剔除已归己方的格子、缺陷格和对方校准区。
      • 双方同时闭合时，从同一局面算候选格。只被一方圈到的格子归该方，两方都圈到就保留原归属。格子的归属和轮廓可以共存，先保留新占格上的轮廓，再清掉完成闭合方自己的全部轮廓。
      • 报废后的下一回合是第 1 个停机回合。重启时朝向和开局一样，落到出生点也会扫过对方轮廓。处理完重启带来的报废后，裁判给仍在场且站在自家领地外的束斑补上当前位置的轮廓。
      • 按时、格式正确的反向命令仍算有效回复。停机期间的回复只用来记耗时和错误。

      圈完地怎么算分

      把自己领地里每格的分值加起来，再扣掉露边的成本。每回合结束都重算一次。

      每凑满 3 条露边，扣 1 分

      只检查自己校准区外的己方领地。格子的某条边挨着无主格、对手领地、缺陷或棋盘外，就算一条露边。

      校准区 9 分，外加 8 个空白格和 1 个高分格
      9 + 8 × 1 + 1 × 3 = 20
      9 条露边扣 3 分
      9 ÷ 3 = 3
      蓝方当前得分
      20 − 3 = 17 分

      怎么分胜负

      一局怎么赢

      打满 600 回合后按下面的顺序比，前一项打平才看下一项。

      1. 1
        最后一回合结束时，分高的赢
      2. 2
        领先回合更多的一方赢只看每回合结束时谁领先。
      3. 3
        累计回复用时更短的一方赢

      三项都一样时，由主办方裁定。胜方记 1 胜，负方记 1 负。

      一场怎么赢

      初赛正式对决中，每对队伍交手一场，在 3 张固定地图上各打 2 局，共 6 局。天梯练习每场用 1 张随机地图，打 2 局。每张图第 2 局都互换出生点。

      整场先比赢了几局。初赛排名看正式对决累计赢了几局，胜局一样就比谁输得少，再比队伍编号（小的在前）。排名最高的 16 支符合资格的队伍晋级。

      整场胜局数打平、构建失败怎么算

      双方 Bot 构建成功时，正式对决按固定地图顺序安排各局。同场各局可以同时打，结果按原定顺序登记。所有预定局结算后，胜局多的一方赢。

      胜局数相同，只合计正常结束的局，还是按单局那三项的顺序比总和。每一局都是双败时，整场双败，胜方留空。其余情况若没有正常结束的局，或三项总和都一样，由主办方裁定整场胜方，已经登记的胜负局照算。

      只有一方因自身提交构建失败时，该方整场判负，对手获胜。整场原定打几局，就给双方分别记几局负和胜。双方都因自身提交构建失败时，整场双败，双方各按原定局数记负。

      每回合 200 毫秒与技术判负

      回合回复从平台发出请求开始计时，到收到完整回复为止。

      阶段时限超时或失败怎么办
      程序就绪启动后 10 秒到时还没就绪，技术判负
      回合回复200 毫秒超时、格式无效或连接失败，记 1 次错误

      本局累计 10 次错误，或 Bot 在开局或回合阶段退出（包括内存超限被终止），也会技术判负。裁判在开局结束时，或收齐当回合双方的响应结果后一起判定。双方都通过才结算这一回合。

      只有一方技术判负时，本局立即结束，对手获胜。双方在开局阶段或同一回合触发就是双败，各记 1 负，胜方留空。得分和领先回合数取上一次结算时的值，一回合都没结算过就取开局 9 分、领先 0 回合。

      累计响应时间按微秒加总所有已发出的回合请求，包括因技术判负而未结算的回合。按时收到完整回复就记实际耗时，格式错了也一样。超时、连接被拒或中断时记 200 毫秒。

      参赛指南

      一、下载材料包

      下载选手材料包（ZIP）

      解压后得到 player-kit/ 目录。提交代码需要 Git，本地对战需要 Python 3.9 或以上版本。开发 C++ Bot 还需 CMake 3.16 或以上版本和 C++17 工具链，开发 Java Bot 还需 JDK 17 和 Maven。接口和开发说明见包内的 README.md。

      二、提交代码

      1. 克隆本队仓库

        在 player-kit 的上一级目录打开终端。把命令中的 team001 换成门户「队伍管理」里仓库地址所显示的本队编号，格式为 teamNNN。

        cd player-kit
git -C bots clone https://codehub.corp.example/hackathon2026/team001.git

        Git 会在 bots/ 下创建同名目录。后续命令中的 team001 也按本队编号替换。

      2. 复制并修改模板

        克隆本队仓库后，从 player-kit/bots/ 中选择所用语言的模板，把该模板目录里的文件复制到本队仓库根目录。

      3. 运行本地对战

        在 player-kit/ 中任选一个模板试跑，提交前再用本队代码打一局。Python Bot 有额外依赖时，先在运行引擎的 Python 环境中执行 python -m pip install -r bots/team001/requirements.txt。

        engine 命令

        python -m engine P1 P2 [--seed SEED]
        P1
        第一个 Bot（必填），填写 bots/ 下的目录名（如 team001）或包含 bot.json 的目录路径。
        P2
        第二个 Bot（必填），目录填写方式与 P1 相同。
        --seed SEED
        省略时随机选取地图种子。填写整数种子可复用同一张地图。
        # 按使用的语言任选一行试跑模板
python -m engine my_bot_python bot002
python -m engine my_bot_cpp bot002
python -m engine my_bot_java bot002

# 提交前用本队代码与另一个 Bot 对战
python -m engine team001 my_bot_python --seed 42

      4. 推送到 Codehub

        本地 master 已跟踪 origin/master 时，提交后可直接用 git push。

        cd bots/team001
git add .
git commit -m "提交参赛代码"
git push

        首次从本地 master 推送且尚未设置上游时，把最后一行改为 git push -u origin master。若本次代码在其他本地分支，使用 git push origin HEAD:master。

        在 Codehub 的 master 分支看到本次提交，即视为交卷成功。正式比赛以锁仓时 master 分支上的版本为准。

      三、天梯对决

      天梯开放后，确认本队 master 分支上已有代码，然后在天梯榜选择其他队伍或基准 Bot 发起挑战。

      四、对局回放
