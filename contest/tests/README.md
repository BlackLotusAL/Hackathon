# Contest 测试用例

使用 CPython 3.9.11，在 `contest/` 目录执行。测试只使用标准库，HTTP 和归档场景使用本机测试服务及临时目录。

```sh
python -B -m tests --level L0
python -B -m tests --level all
python -B -m tests --level all --list
```

## L0 用例

| 编号 | 功能与关键预期 |
| --- | --- |
| L0-001 | 初赛和决赛裁判入口无令牌执行完整对局，保留协议版本头；各完成 600 回合、0 错误，生成 600 帧和 602 条公开观测，决赛包含潜像字段，归档通过同版复核。 |
| L0-002 | 单局四项指标全同或双方启动崩溃时，胜方为空、执行暂缓生效，整场查询保持待定。 |
| L0-003 | 技术判负包含最后一次已发回合请求的整数微秒耗时；第 9 次请求触发判负时累计为 [1800000, 9009]，舍入后的伪结果被拒绝。 |
| L0-004 | 同回合双方技术判负时，包含最后请求耗时后再比较；累计 [9978, 8036]，1 号获胜。 |
| L0-005 | 正式对决 3∶3 时，依次比较六局累计得分、订单奖励、领先回合数和响应时间。前三项取较高值，耗时取较小值，四项全同暂缓结算。 |
| L0-006 | 正式六局的地图哈希、换边和指标归队正确。满六局后查询得到最终胜负和按局序排列的对局结果，重启后结果一致。 |
| L0-007 | 平台故障重跑沿用原计划、递增尝试后缀。后续构建双败时，已生效的替代尝试仍在赛果中，构建证据单独引用。 |
| L0-008 | 乱序查询天梯结果时可取得同赛段双方最近确认的前序对决，双方共享的前序编号只出现一次。 |
| L0-009 | 三队单循环包含构建双败及故障重跑；共 3 场、18 预定局，有效 12 局、豁免 6 局，作废和重跑各 1 次；排名、进度和结果三表一致，确认前禁止导出。 |
| L0-010 | 退赛保留已完成赛果；未开打场次按整场处理，在途执行保留待处理状态，进度计数正确。 |
| L0-011 | 经 HTTP 和归档夹具验证初赛批量查询与 Contest 重启重跑，有效 18 局，初赛 XLSX 引用 `run-1.2`。核对天梯整场胜负和对局明细。 |
| L0-012 | 计划创建中途失败时，对决、预定局和执行尝试整体回滚；修正后可正常创建六局，从 run-1.1 开始。 |
| L0-013 | 并发领取不能重复获得同一 run_id；初赛可领取不同执行，决赛按场串行，后场保持待提交。 |
| L0-014 | Portal 提交保持幂等。覆盖无效编号、未知编号、已受理待定及未注册路径的响应，并核对 Arena 无效响应后的待定状态。 |
| L0-015 | 初赛和决赛的归档缺文件、得分或日志计时篡改、地图哈希不符、队伍座位颠倒、未知引擎版本、缺公开观测或提交号均被暂缓。20 组异常记录原因并保持待定。 |
| L0-016 | 天梯两局换边后，1:1 记平局、2:0 记明确胜方；第一局后不结算，最终胜负局数、开始时间和有效 runs 顺序正确。 |
| L0-017 | 初赛正式、决赛正式及天梯构建单败、双败共 9 组组合，按预定局数结算。结算后 `runs` 和 `games` 为空，`build_run_id` 正确。 |
| L0-018 | 真实 HTTP 覆盖后台白名单各取值、CIDR 匹配及转发头校验。缺账号返回 401、缺写标记返回 403，拒绝写入不改变名单。Portal 接口在后台拒绝访问时仍可用。 |
| L0-019 | 空名单不能编排；编排后名单变更被拒绝，相同名单导入和重复编排幂等，场数、局数及状态不变。 |
| L0-020 | 正式六局有效结果形成 3∶3 且四项累计指标全同时，六局保持生效，整场查询仍为待定。 |
| L0-021 | 覆盖绝对路径，以及配置文件的归档路径相对 Contest 安装目录、数据库路径相对配置文件目录的解析。核对命令行参数相对当前工作目录并覆盖配置文件。 |
| L0-022 | 损坏 JSON、无效端口、未知字段、缺少共享归档路径及缺少或无效的 Arena URL 均在写入数据前被拒绝。 |
| L0-023 | Contest 按命令行指定的 Arena URL 提交、查询单局和读取运行统计。Portal 可主动取得构建双败结算。 |
| L0-024 | 裁判任务只需 Bot 地址，从任务文件读取赛段，显式赛段参数可覆盖，缺省保持初赛；旧环境变量不再提供赛段或地图。 |
| L0-025 | 初赛批量查询按 100 条拆批，只包括已受理或提交未确认、尚未取得终态的当前尝试。缺失编号与同批有效结果分别处理，重跑前的旧响应不能落库。 |
